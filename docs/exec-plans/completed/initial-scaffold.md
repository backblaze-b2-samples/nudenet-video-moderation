Scaffold a new B2 sample from `vibe-coding-starter-kit`. Source of truth for the

---

## 1. Purpose

`nudenet-video-moderation` is a self-hosted, open-source **Trust & Safety pipeline**
that screens user-generated video for NSFW / unsafe content before publication.
A T&S operator ingests a raw UGC video into Backblaze B2, the pipeline samples
frames with ffmpeg, classifies each frame **locally** with **NudeNet** (an ONNX
detector — no external API, no second key), writes flagged frame crops and a
per-video moderation report JSON back to B2, and appends the result to an
aggregated violations manifest. The web app is the reviewer's console: a
dashboard of moderation activity, a **review queue** of per-video reports, a
per-video report detail with the per-frame detection table + flagged-frame grid,
and a human-in-the-loop decision (approve / reject / escalate). It is for
platform Trust & Safety teams and anyone who wants to see B2 act as the storage
layer for high-velocity UGC ingest where flagged crops + JSON reports multiply
stored object count into the millions.

**Safety note (governs the build + verify):** NudeNet is a *defensive* content
classifier. The pipeline NEVER needs, bundles, downloads, or generates NSFW
media. The end-to-end verify uses a **synthetic benign clip** generated by the
bundled ffmpeg (`testsrc` / solid-color frames); a clean clip legitimately
produces a "Clean — 0 violations" report, which is the common T&S case and is
fully presentable. NudeNet also detects non-explicit classes (FACE, FEET, BELLY)
that fire on ordinary clothed footage — so a benign clip can still populate the
detection table while the flagged grid stays empty, demonstrating the
detect-but-don't-flag policy without any unsafe content.

### ADD (new for `nudenet-video-moderation`)
Backend (`services/api/app/`):
- `service/frames.py` — ffmpeg frame extraction via the **imageio-ffmpeg bundled
  static binary** (`imageio_ffmpeg.get_ffmpeg_exe()`), so it works from a fresh
  clone with no system ffmpeg. Configurable sampling: `fps` mode (default 1 fps)
  and `keyframes` mode (`-skip_frame nokey`). Writes frames to a temp dir.
- `service/classifier.py` — NudeNet wrapper. Lazy-loads a process-wide
  `NudeDetector` singleton (import inside the function so structure/no-network
  tests don't pull the model). `classify_frame(path, threshold) -> [detections]`;
  each detection `{class, score, box}`. CPU is the default execution provider;
  GPU is optional (see §3 deployment).
- `service/moderation.py` — pipeline orchestration: ingest → extract frames →
  classify each → select violations (score ≥ threshold AND class ∈
  `VIOLATION_LABELS`) → crop+upload flagged frames → write report JSON → append
  manifest. Also: list reports, get report, set review decision (edit), re-run
  (run), delete report+artifacts (delete, scoped to `moderation/.../<video_id>/`).
- `runtime/moderation.py` — routes (see §3).
- `types/moderation.py` — `FrameDetection`, `FrameResult`, `ModerationReport`,
  `ReviewDecision` (enum: pending/approved/rejected/escalated), `ManifestEntry`,
  `ModerationStats`.

Frontend (`apps/web/src/`):
- `/` Dashboard → moderation overview (stats + activity chart + recent scans).
- `/jobs/new` → **Create** form: video dropzone, sample-mode `Select`, threshold
  number input (default-hint via `FormDescription`), optional advanced violation-
  label multi-select. Submits multipart → ingest + synchronous pipeline run.
- `/jobs` → **Review Queue** = the **sample-specific asset explorer scoped to
  `moderation/reports/`** (satisfies the mandatory add-an-asset-explorer rule).
  Table of reports: video, verdict badge, flagged-frame count, frames analyzed,
  review decision, timestamp. Powered by the manifest (one GET).
- `/jobs/[videoId]` → **Read** detail: verdict, per-frame detection table,
  flagged-frame thumbnail grid (presigned), the raw report JSON, plus the
  **Edit** controls (review decision `Select`/`RadioGroup` + notes), **Run**
  (re-run pipeline) button, and **Delete** button.
- `/files` → bucket explorer (KEEP).
- `/settings` → Moderation defaults form (default threshold, default sample mode).
- `lib/queries.ts` / `lib/api-client.ts` → add moderation query keys + fetchers.

### Note on bucket explorer vs asset explorer
Both are present and distinct, per the non-negotiable rule: `/files` browses the
ENTIRE bucket (raw uploads + all moderation artifacts); `/jobs` (Review Queue) is
the sample-scoped explorer over `moderation/reports/` only. No tension to record.

## 3. B2 surface (S3-compatible only — no b2-native)

| Operation | Used by |
|---|---|
| `put_object` | raw video ingest (`uploads/raw/<video_id>/<file>`), flagged frame JPEGs (`moderation/flagged/<video_id>/frames/`), report JSON (`moderation/reports/<video_id>.json`), manifest (`moderation/manifest.jsonl`) |
| `list_objects_v2` (paginated) | review queue, bucket explorer, stats |
| `get_object` | read report JSON, read raw video for processing, read manifest |
| `head_object` | metadata / existence checks |
| `generate_presigned_url` | inline preview of flagged frames + video in the UI, downloads |
| `delete_object` | delete report + its flagged-frame artifacts (scoped to the video_id prefix) |

**No b2-native API anywhere** — boto3 S3 client only, per parent CLAUDE.md.

**Aggregated manifest & the no-append reality:** S3 has no append. The manifest
(`moderation/manifest.jsonl`) is maintained read-modify-write: read current
object, append the new entry line, `put_object` it back. This is an honest
teaching point about object storage (documented in the feature doc). Not
concurrency-safe under parallel jobs — note it as a production caveat, fine for
the sample. The manifest is the cheap data source for the dashboard + review
queue (one GET vs N report reads).

**Env vars — enforce Standard #3 (the starter deviates; this is a known recurring
fix).** Rename in `settings.py`, `main.py` (REQUIRED/PLACEHOLDER), `b2_client.py`,
`.env.example`, README, infra:
- `B2_KEY_ID` → **`B2_APPLICATION_KEY_ID`**
- `B2_APPLICATION_KEY` (unchanged)
- `B2_BUCKET_NAME` (unchanged)
- `B2_ENDPOINT` → **derive from `B2_REGION`**: `https://s3.{B2_REGION}.backblazeb2.com`;
  add **`B2_REGION`** (default `us-west-004`) and pass `region_name` to the boto3
  client (correct S3v4 signing).
- `B2_PUBLIC_URL` → **`B2_PUBLIC_URL_BASE`**

Plus app config: `MODERATION_THRESHOLD` (default `0.25`), `SAMPLE_MODE`
(`fps`|`keyframes`, default `fps`), `SAMPLE_FPS` (default `1`), `VIOLATION_LABELS`
(comma-separated, env-configurable — default below), `MAX_VIDEO_SIZE`.

**Custom user agent:** `user_agent_extra` → **`b2-nudenet-video-moderation`**
(was `b2ai-oss-start`). Set on the single boto3 client in `b2_client.py`.

### Moderation routes
- `POST /moderation/jobs` — multipart video → ingest + run pipeline → report (CREATE+RUN)
- `GET /moderation/reports?limit=` — list reports from manifest (READ list)
- `GET /moderation/reports/{video_id}` — full report JSON (READ detail)
- `PATCH /moderation/reports/{video_id}` — set review decision + notes; optional
  threshold re-evaluation against cached detections (EDIT)
- `POST /moderation/reports/{video_id}/rerun` — re-extract + re-classify (RUN)
- `DELETE /moderation/reports/{video_id}` — delete report + flagged artifacts,
  scoped to the `<video_id>` prefix (DELETE)
- `GET /moderation/stats` + `GET /moderation/stats/activity?days=` — dashboard

## 4. Key features (seed README + `docs/features/*`)

All features are **`deployment: local`** — no external API provider, no second
key, B2 credentials only. (Description: "Runs on local OSS — no second API key.")
No "Suggested stack" / Genblaze mention in the brief, so **no Genblaze routing.**

1. **Video ingest to B2** — UGC videos uploaded to `uploads/raw/<video_id>/`.
   `deployment: local` (B2 only). Cost: $0 (B2 storage only).
2. **Frame sampling (ffmpeg)** — configurable 1 fps or keyframes-only extraction
   via the imageio-ffmpeg bundled binary. `deployment: local`. Cost: $0.
3. **NSFW classification (NudeNet)** — CORE local ONNX detector; per-frame labels
   + confidence + bounding boxes. `deployment: local` (no provider/key; ONNX
   model ships in the `nudenet` wheel → first inference works offline). Cost: $0.
   **CPU is the default**; inference on sampled frames is light. Optional GPU path
   = swap `onnxruntime` → `onnxruntime-gpu` (CUDA). NudeNet runs on onnxruntime,
   not torch, so the CUDA→MPS→CPU rule maps to ONNX execution providers; MPS has
   no first-class onnxruntime EP, so the local fallback chain is CUDA → CPU, with
   CPU as the shipped default. Record this as the local-deployment justification.
4. **Flagged-frame extracts + report JSON** — frames whose detection score ≥
   threshold AND class ∈ `VIOLATION_LABELS` are written as JPEG crops to
   `moderation/flagged/<video_id>/frames/`; a per-video `report.json` is written
   to `moderation/reports/`. `deployment: local`. Cost: $0.
5. **Review queue + human decision** — reviewer console over `moderation/reports/`
   with approve / reject / escalate decisions persisted into the report.
   `deployment: local`. Cost: $0.
6. **Aggregated violations manifest** — `moderation/manifest.jsonl` powering the
   dashboard + queue. `deployment: local`. Cost: $0.

**Default `VIOLATION_LABELS`** (the genuinely-NSFW exposed NudeNet classes;
env-configurable so policy can be tuned, mirroring the class→role-mapping rule):
`FEMALE_GENITALIA_EXPOSED, MALE_GENITALIA_EXPOSED, FEMALE_BREAST_EXPOSED,
BUTTOCKS_EXPOSED, ANUS_EXPOSED`. All other detected classes (FACE_*, FEET_*,
BELLY_*, ARMPITS_*) are recorded for transparency but do NOT flag a frame.

### Primary entity & lifecycle (UI completeness)
**Primary entity: the moderation report (one per video, keyed by `video_id`).**
All five lifecycle verbs are user-accessible and built — `omitted_ui_verbs: []`:
- **create** — `/jobs/new`: upload a video + run the pipeline.
- **read** — `/jobs` (list/queue) + `/jobs/[videoId]` (detail).
- **edit** — `/jobs/[videoId]`: set the human review decision + notes (and
  optional threshold re-evaluation). Directly serves the "human review queue"
  use case.
- **run** — `/jobs/[videoId]`: re-run the pipeline (re-extract + re-classify).
- **delete** — `/jobs/[videoId]`: delete the report + its flagged-frame artifacts.

### Form UX conventions
- **Create form (`/jobs/new`):** video file (dropzone); **sample mode** — finite
  set → `Select` ("1 fps", "Every 2 seconds", "Keyframes only"); **threshold** —
  number input with a `FormDescription` safe-default hint (0.25), guidance only,
  no autofill button; **violation labels** (advanced/optional) — multi-select,
  finite set. Create-only default hints surfaced as placeholder/description.
- **Edit form (review decision):** **decision** — finite set → `RadioGroup`/
  `Select` (Pending / Approved / Rejected / Escalated); **notes** — `Textarea`.
  Opens pre-filled with the report's current decision (no default-hint rule).
- Exemplar: `apps/web/src/components/settings/settings-form.tsx`.

## 7. Dependency pinning (CRITICAL — unpinned ML breaks clean install)

In `services/api/requirements.txt`, pinned window (heavy ML imports are LAZY so
structure/no-network tests pass without the model; the real model-load is covered
by end-to-end verify):
- `nudenet>=3.4.2,<3.5`
- `onnxruntime>=1.17,<2`
- `opencv-python-headless>=4.9,<5` (headless — no libGL on servers)
- `imageio-ffmpeg>=0.5,<0.6` (bundled static ffmpeg)
- `numpy>=1.26,<2.2`
- Keep `Pillow` only if used for crop/thumbnail; otherwise drop with PyPDF2.

**Builder MUST verify end-to-end, not just import:** create a synthetic benign
clip with the bundled ffmpeg, run the full pipeline (extract → NudeNet load →
classify → report), and confirm a clean report is produced. Import-only checks
are a false green for ML samples. Add a no-network signature/structure test that
does NOT load the model (keeps `test:api`/`check:structure` fast and offline).
